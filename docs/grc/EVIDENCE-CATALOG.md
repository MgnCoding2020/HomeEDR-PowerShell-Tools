# Evidence Catalog (Draft)

This document defines the evidence artifacts generated by the Home EDR monitoring framework and how they support structured control validation.

The purpose of this catalog is to:

- Identify what evidence is produced
- Clarify what each artifact represents
- Establish collection cadence expectations
- Define retention considerations
- Support traceability over time

---

## How to Use This Document

Each entry includes:

- **Artifact Name**
- **Source Script**
- **Purpose**
- **Control Alignment (Conceptual)**
- **Collection Cadence**
- **Storage Location**
- **Retention Notes**
- **Sensitivity Considerations**

---

## EC-01: Endpoint Health Snapshot

**Artifact Name:**  
`HealthSnapshot_<timestamp>.txt`

**Source Script:**  
`scripts/HealthSnapshot.ps1`

**Purpose:**  
Provides a structured snapshot of endpoint posture including system information, update status, firewall configuration, Defender status, disk health, and event log summaries.

**Control Alignment (Conceptual):**
- Continuous monitoring
- Configuration management visibility
- Security state awareness

**Collection Cadence:**  
Daily or weekly (environment dependent)

**Storage Location:**  
`snapshots/` (or configured output directory)

**Retention Notes:**  
Older snapshots may be archived under date-based structure for historical traceability.

**Sensitivity Considerations:**  
May contain:
- Hostnames
- Local user identifiers
- Installed software listings
- Network configuration details

Sanitized versions should be used for public repository examples.

## EC-02: Services Drift Report

**Artifact Name:**  
`ServicesDrift_<timestamp>.txt`

**Source Script:**  
Service comparison logic within monitoring scripts

**Purpose:**  
Identifies deviations between baseline service configuration and current system state.

**Control Alignment (Conceptual):**
- Configuration integrity monitoring
- Change detection
- Unauthorized modification awareness

**Collection Cadence:**  
Aligned with scheduled snapshot frequency

**Storage Location:**  
`alerts/`

**Retention Notes:**  
Drift artifacts should be preserved for review and incident analysis.

**Sensitivity Considerations:**  
May reveal service configuration and system roles.

---

## EC-03: Scheduled Task Drift Report

**Artifact Name:**  
`ScheduledTaskDrift_<timestamp>.txt`

**Source Script:**  
Scheduled task monitoring components

**Purpose:**  
Detects creation, removal, or modification of scheduled tasks compared to baseline.

**Control Alignment (Conceptual):**
- Persistence monitoring
- Unauthorized task detection
- Monitoring mechanism validation

**Collection Cadence:**  
Aligned with snapshot cycle

**Storage Location:**  
`alerts/`

**Retention Notes:**  
Drift events may indicate persistence mechanisms and should be retained.

**Sensitivity Considerations:**  
May contain local file paths and user context references.

---

## EC-04: Consolidated Drift Summary

**Artifact Name:**  
`PostureDriftSummary_<timestamp>.txt`

**Source Script:**  
Consolidation logic (currently the three Posture scripts)

**Purpose:**  
Provides an aggregated overview of detected deviations across monitored categories.

**Control Alignment (Conceptual):**
- Monitoring effectiveness review
- Risk triage support
- Operational awareness

**Collection Cadence:**  
Generated per snapshot cycle

**Storage Location:**  
`alerts/` or designated summary directory

**Retention Notes:**  
Supports trending and longitudinal analysis.
